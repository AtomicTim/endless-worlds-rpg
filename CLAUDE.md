## ⚡ FOUNDATIONAL RULES (Read Before Every Session)

### 1. World Assets Are Permanent
Write-once constitution. `ignoreDuplicates: true`. SVG backfilled separately.

### 2. Movement Is Absolute
MOVE always succeeds. World state saved immediately after every MOVE.

### 3. Location Is Authoritative State
`current_location_id` always correct. Saved immediately on MOVE.

### 4. Actions Are Permitted By Default
Plausible actions always attempted. Narrator describes outcomes only.

### 5. Objects Mentioned Exist
EXAMINE/INTERACT resolver confirms object_confirmed=true. Prepended as first narrator fact.

### 6. Dialogue Is Consistent
All dialogue — clicked option OR typed freely — identical pipeline. NPC name passed directly, never re-extracted from AI output.

### 7. The AI Has Exactly Three Roles
**Generator:** Creates assets (locations, NPCs, items, lore) on first encounter. Once created, immutable.
**Bridge:** Describes results of player actions in context of current game state. Does NOT decide outcomes, add unprompted events, or speak for the player.
**Thread:** Plants subtle story breadcrumbs. Never forces, never blocks, never invents player knowledge.

The AI NEVER:
- Speaks in the player's voice or attributes dialogue/thoughts/memories to them
- Invents NPC behavior outside their locked constitution + trust score
- Retcons or reinterprets established world assets
- Takes any action the player didn't initiate

## 🎮 Game System Architecture (Core Principle)

This is an RPG game system first. Every entity — NPC, location, item, faction — is a game asset with defined states and characteristics. The AI generates those assets on first encounter, then becomes a pure interpreter of player actions against those locked assets.

**NPC interaction model:**
- NPC constitution (appearance, personality, role, faction) — locked on first meeting
- NPC trust score — tracked in npc_registry, updated by resolveDialogue()
- NPC disposition — derived from trust score, read from npc_registry
- NPC response — generated by narrator using constitution + trust as hard facts
- NPC name — read from world_assets (name_known ? name : placeholder)

**Nothing about an NPC comes from the AI's current response. Everything comes from stored game state.**

## Narrator Architecture

**The narrator is a pure interpreter, not a decision-maker.**

- **Tier 1** (2-3 sentences): PRESENT repeated, USE_ITEM, simple CUSTOM
- **Tier 2** (4-6 sentences): EXAMINE, ATTACK, INTERACT, DIALOGUE, first NPC
- **Tier 3** (80-120 words): ARRIVING at NEW location, major moments
- GOLDEN RULE: honor action, yes-and, never speak for the player
- MOVE: always arrives
- EXAMINE/INTERACT: object_confirmed prepended as first fact
- ACTIVE NPC CONTEXT: full constitution + trust + disposition injected as facts
- PLAYER IS BLANK SLATE: narrator never attributes history/knowledge/relationships to player
- log_summary: 12-word max terse fragment

---

## Action Classification

- **FAST PATH**: equip, unequip, drop, read lore
- **NARRATIVE PATH**: MOVE, ATTACK, INTERACT, EXAMINE, DIALOGUE, USE_ITEM(CONSUMABLE), search CONTAINER
- **DIALOGUE**: NPC name passed as parameter, not re-extracted
- **MOVE**: always MOVE_SUCCESS + immediate world state save
- **EXAMINE/INTERACT**: always success=true + object_confirmed
